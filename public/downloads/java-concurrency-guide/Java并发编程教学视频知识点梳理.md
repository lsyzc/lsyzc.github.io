## 6. 优雅停止线程

原字幕：[第 6 节](<6-【莲城的老李】—强停线程的stop()是Bug！要学会优雅的停止线程—【2025-04-09】-中文.txt>)

- 用户 ID 和姓名分步更新示例；即使使用同步方法，强制停止仍可能暴露更新一半的数据。

## 34. CountDownLatch 与 CyclicBarrier

原字幕：[第 34 节](34-【莲城的老李】—倒计数与循环倒计数？多线程协同利器利器如何选—【2025-05-21】-中文.txt)

- JUC：`java.util.concurrent`，JDK 1.5 引入；并发工具、接口及线程安全容器，提及 `ConcurrentHashMap`。
- `CountDownLatch`：一个或多个线程等待一组操作完成的倒计数协作机制。
- 构造初始计数，可代表任务数或操作数；`countDown()` 减一；计数归零释放等待者。
- `await()` 无限等待；`await(timeout, unit)` 限时等待、布尔返回值；中断异常。
- `getCount()` 查询当前计数，用于调试测试。
- 初始计数不可重新设置；归零后不能重置为下一轮，另一轮需创建新实例。
- 两线程完成两次计数后主线程继续；去掉倒计数、初始数大于实际完成次数导致一直等待。
- `countDown()` 的位置决定其表示的是哪一步完成；打印语句出现先后不等于整个线程完成次序。
- 不同任务耗时、等待期限足够/不足的超时实验。
- 与线程池组合：提交多个任务、逐一倒计数、主线程等待归零后汇总并关闭。
- `CyclicBarrier`：多个参与线程在屏障互相等待，全部到齐后一起继续。
- 两种构造：参与方数量，以及可选 `Runnable barrierAction`。
- `await()` 与 `await(timeout, unit)`；中断、超时及屏障破坏相关异常。
- `await()` 的到达索引：先到者索引较大，最后到达者为 0；转换成符合习惯的到达序号。
- 所有参与方到齐触发屏障动作，再继续各线程后续工作；线程池模拟集体就位。
- 循环使用：正常触发后自动开始下一代，无需每轮手动 `reset()`。
- `reset()` 强制重置当前屏障代次，不是更改构造时参与方数量。
- 等待期间强制重置会使已等待线程收到 `BrokenBarrierException`；迟到线程进入新一代屏障。
- 两线程不同延迟、重置时机、加入第三线程的实验；新一代参与方不足导致永久等待。
- 两工具的对比：等待一组操作完成与参与线程相互集合；一次计数与循环屏障；计数完成与屏障触发。

- 获取与释放正确配对，避免许可证泄漏；只有成功获取的路径才应归还相应许可。
- 六线程车辆通行示例：配置三个或两个许可，观察同时运行数量与后续进入时间。
- 用休眠模拟持有许可的耗时；超时短于或长于持有时间时的不同结果。
- 信号量用于限制并发进入数量，不自动保证多个进入者对共享数据操作的原子性。
- 万线程计数、千个许可、`CountDownLatch` 等待汇总示例；`count++` 仍会竞争丢失更新。
- 对共享计数额外加同步锁，验证预期结果；并发数量控制与共享数据保护的职责区分。
- 应用场景：并发限流、登录/在线人数控制、数据库连接数量控制。
